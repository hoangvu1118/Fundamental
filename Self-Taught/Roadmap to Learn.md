## Pragmatic Programmer
### Care about your craft
The point is, you should always know what you are building and developing
### Think about your work
Constantly thinking about your project, critically question about it, be realistic, how it can be changed, updated, and optimized
It is not just a 1 time thinking --> it is every day and on every development.
### Provide Options, Don't make excuses
Never rushing to tell anyone, your boss, your co-worker that something 
+ Cannot be done
+ Late
+ Broken
*Instead*: Recheck your excuses, does it sound ridiculous ?
Try some other option in advance, make sure that you try everything
Give them reasonable options, example `the code need refactoring, need prototyping, better testing` 
Finally, admit that you need help, if problem cannot be solved

### Don't LIVE with broken windows
Broken windows : *bad designs, wrong decision, poor code unrepaired*
>[!Important] Tip
>Fix each one as soon as it is discovered
>In case, NOT ENOUGH Time to fix
>+ Comment the code out
>+ Display the `NOT IMPLEMENT`
>+ Substitute with *dummy dataset*
>
>**Do something to prevent the damage / mitigate 'em**

>[!Tip] Moral of the story
>If we work in the project in which, the code is badly designed, poorly coded, no clear structure
>Then it is easy to *ignore the small errors* which lead to serious performance degradation later on
>
>However, If we are working in a project that is perfectly design, clean code
>Then we will make ourselves to follow that pattern, to *WORK with high concentration* with the believe that we will not ruin the project
